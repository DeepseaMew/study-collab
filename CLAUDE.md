# Study Collab — House Rules

## Stack
- Flutter stable (pinned); Dart 3.x.
- State: Riverpod 2 + riverpod_generator.
- Routing: GoRouter; every route declared in lib/app/router.dart.
- Networking: Firebase SDK only — never import 'package:http/http.dart' for Firebase calls.
- Auth: firebase_auth (Email/Password + Google Sign-In).
- Database: Cloud Firestore (real-time sync).
- Storage: Firebase Storage (avatars, session files).
- Models: Freezed + json_serializable; never hand-roll (de)serializers.
- Notifications: firebase_messaging (FCM).

## Firebase Project
- Project ID: study-collab (Firebase console)
- Region: asia-southeast1
- Firestore mode: production (rules enforced)

## Do not edit
- **/*.g.dart, **/*.freezed.dart — run codegen instead.
- lib/firebase_options.dart — auto-generated by FlutterFire CLI.
- ios/Pods/**, android/app/build/**, generated_plugin_registrant.*

## Firestore Collections
- /users/{uid}
- /sessions/{sessionId}
- /sessions/{sessionId}/messages/{messageId}  ← subcollection
- /sessions/{sessionId}/files/{fileId}         ← subcollection
- /session_members/{sessionId}_{uid}
- /calendar_events/{eventId}

## Conventions
- Errors: domain errors are sealed classes (lib/domain/errors/); never throw strings.
- Logs: use lib/infra/logger.dart; never print(); never log PII.
- Analytics: every Firebase Analytics event declared in lib/infra/analytics_events.dart.
- Feature flags: use Firebase Remote Config via the feature-flag skill.
- Firestore writes: always use batch or transaction for multi-document updates.

## Security Rules
- Security rules live in firestore.rules and storage.rules at repo root.
- Never deploy rules without running: firebase emulators:exec "flutter test"
- All rules changes go through security-reviewer agent before deploy.

## Workflows
- Tests: flutter test && flutter test integration_test
- Codegen: dart run build_runner build --delete-conflicting-outputs
- Emulator: firebase emulators:start --only auth,firestore,storage
- Deploy rules: firebase deploy --only firestore:rules,storage
- Full deploy: see docs/runbooks/release.md

## Security
- No PII in logs. No Firebase API keys hardcoded — use google-services.json / GoogleService-Info.plist (gitignored).
- Firestore Security Rules enforce all read/write access — never rely on client-side checks alone.
- Firebase Storage rules mirror Firestore membership checks.
- Service account keys never committed; use CI secrets.
